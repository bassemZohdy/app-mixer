### Bugs and correctness
- [x] P4-01 Fix the CLI entry point on Windows
  - Found: `packages/cli/src/index.ts` detected the entry with `process.argv[1]?.endsWith('/dist/index.js')`; on Windows `argv[1]` uses backslashes, so `node packages\cli\dist\index.js create demo` exited 0 and created nothing (reproduced 2026-11-06). Fixed 2026-11-06: the entry is compared by resolved path (case-insensitively on Windows), and a test runs the command through absolute and relative paths, the usage error and an invalid name (verified on Windows and in CI).
- [x] P4-02 Stop recording pre-effect failures as uncertain actions
  - Found: `SqliteAgentActionJournal.invoke` and `PostgresAgentActionJournal.invoke` mark the action `uncertain` for any error thrown by `dispatch`, including `Capability forbidden`, `Invalid capability input`, `Capability not found` and delegation refusals that `CapabilityRegistry.invoke` raises before `execute` (and audits as `denied`/`invalid`/`not_found`). The run then settles `uncertain` and needs manual reconciliation although nothing was applied. Fixed 2026-11-06: the registry marks every error thrown before `execute` with the non-enumerable `Symbol.for('app-mixer.effect') === 'none'` (`markNoEffect`/`hadNoEffect`, usable without a package dependency), the configured runtime marks its own activity and delegation refusals, and both journals return a marked action to `ready` (or `failed` once attempts are exhausted) and rethrow the original error; unmarked errors stay uncertain. Tests cover each refusal class in core, the SQLite and PostgreSQL journals and a configured run refused by the registry and by the runtime. Typed error classes remain P4-16.
- [ ] P4-03 Replace lifetime caps that count terminal rows with retention
  - Found: `SqliteOfflineQueue.enqueue` counts every row for the principal (succeeded and discarded included), so a principal is refused after 1,000 operations ever and nothing can remove rows; `EncryptedBrowserQueue.enqueue` has the same 1,000 cap per partition and no purge; `SqliteAgentMemory`/`PostgresAgentMemory.put` refuse new IDs once history (tombstones included) reaches `10 × maxEntries`, with no compaction. ### Security hardening
- [ ] P4-13 Remove `'unsafe-inline'` scripts and add headers to the generated app
  - Found: the development review page (`planes.ts`) and the approval review page (`approval-server.ts`) ship inline scripts under `script-src 'unsafe-inline'`; the generated `server.mjs` serves `/` with no Content-Security-Policy, Referrer-Policy or frame-ancestors. Fix: serve the page scripts as separate modules (or nonces), set a strict CSP and the other headers in the generated server, and assert them in the browser smoke tests.
- [x] P4-14 Harden the HTTP and TLS servers that core creates
  - Found: `createControlPlane`, `createDataPlane(Https)`, `createCapabilityServer`, `createAGUIServer`, the generated `server.mjs` and `deploy/local/service.mjs` leave Node's default `requestTimeout`/`headersTimeout`/`keepAliveTimeout`; only `deploy/kubernetes/data-plane.mjs` sets them. The HTTPS variants set `minVersion: 'TLSv1.2'` with no cipher policy. Fixed 2026-11-06: `limitServer` (core and an agent copy, since agent does not import core) applies 10 s header, 30 s request, 5 s keep-alive and 30 s idle timeouts to every server factory and to the generated `server.mjs` (the local service uses the factories); `TLS_POLICY` adds ECDHE AEAD `ciphers` and `honorCipherOrder` to the HTTPS servers and the credential reloader; a test stalls a request body and checks the connection is closed promptly. Found while testing: Node only checks timeouts every 30 s (and ignored `connectionsCheckingInterval` here), so the idle timeout is the prompt cut-off; the AG-UI event stream is exempt from it.
- [x] P4-15 Keep validated identifiers out of SQL text
  - Found: `postgres-agent-memory.ts` builds the HNSW index predicate, the scoped filter and `value::jsonb->>'modelId'='${modelId}'` by string interpolation; safety rests on the `validMemoryId` regex. Fixed 2026-11-06: scope and model identifiers are quoted through one validating helper (`sqlLiteral`: memory-ID alphabet, quotes doubled as a second layer) and a test rejects every quoting character. The query-side filters stay literals on purpose: the HNSW index is partial and its expression holds constants, and the planner only matches the query against it when it holds the same constants (a bound parameter would silently fall back to a sequential scan).
- [ ] P4-16 Typed errors with codes and preserved causes
  - Found: HTTP status mapping is done by comparing message strings (`planes.ts`, `capability-server.ts`, `approval-server.ts`, `event-ingress.ts`, the supervisor's `lostRace` regex, the disconnected importer's `/version conflict|.../`), so a new or reworded message silently becomes a 500 or a wrong class; `remote-promotion.ts`, `remote-control-connector.ts`, `oidc-discovery.ts`, `jwt-jwks-manager.ts` and `notice-https-transport.ts` swallow the cause (`catch{throw Error('… failed')}`). Fix: an `AppMixerError` with `code` and `status`, `cause` attached without secrets, mapping by code, and a test that every thrown code has a mapping.

### Performance
- [ ] P4-17 Cut the round trips of exact search and listings on PostgreSQL
  - Found: `AgentSemanticMemory.search`/`searchHybrid` on `PostgresAgentMemory` page through `list`, which calls `get` per row (three reads and three authorize calls each) and then `get` again per hit, so one query costs more than 3N round trips for N ≤ 1,000 entries; `PostgresAgentDefinitions.list` costs six per agent. Fix: one page read with the fence applied once per page and per-record authorization in memory, a benchmark at `maxEntries: 1000`, and the same for the definition listing.
- [ ] P4-18 Incremental rendering and a renderer benchmark
  - Found: `A2UIRenderer.apply` rebuilds the whole surface with `replaceChildren` on every message, including every keystroke (a field write becomes `updateDataModel` → full re-render with manual focus and selection restore); the React Native and Flutter stores re-snapshot the whole tree too. Fix: a 1,000-component benchmark fixture, data-only updates that patch bound Text and TextField nodes in place, and a parity test that the incremental path matches a full render.
- [ ] P4-19 Avoid decrypting the whole browser queue on every worker pass
  - Found: `BrowserOfflineWorker.pass` calls `EncryptedBrowserQueue.list()`, which unseals every envelope (up to 1,000 AES-GCM decrypts) each interval. Fix: an in-memory cache keyed by `(id, version)` invalidated by the counter, or a pending-only index, with a test that a 1,000-item queue dispatches within a bound.
