# Data Plane request observations

Pass `observe: event => ...` as an option to `createDataPlane` to receive a best-effort observation after each response completes or the client disconnects. Each event contains a fixed route class (`application`, `version`, `live`, `ready`, or `other`), outcome (`completed` or `aborted`), response status class (`2xx`, `3xx`, `4xx`, `5xx`, `other`, or `none` for an aborted response), and monotonic elapsed milliseconds from request handling to response finish or disconnect. Route classes depend on method, exact supported path, and whether health probes are enabled. Raw URLs, publication versions, headers, tokens and actor identifiers are not emitted. A closed connection is recorded at most once.

The callback runs in the server process and must be fast and nonblocking. Synchronous errors and rejected promises are ignored so telemetry failure does not break serving; the host must bound and monitor its exporter queue. An observation is not a durable audit record. Request completion measures server response completion, not confirmation that a client received the response, and excludes work done before the handler begins. An aborted request is separate from an HTTP status and should not automatically be counted as a server error. Hosts can aggregate counts and latency histograms by the bounded fields, supply service and deployment attributes from trusted configuration, and export them through their chosen metrics system. This API is not an OpenTelemetry implementation and does not provide distributed trace context, SLOs, retention or alerts; configure those at the host and collector with appropriate privacy, cardinality and operational ownership.
