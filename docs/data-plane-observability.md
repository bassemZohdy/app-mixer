# Data Plane request observations

Pass `observe: event => ...` as an option to `createDataPlane` to receive a best-effort observation after each response completes or the client disconnects. Each event contains a fixed route class (`application`, `version`, `live`, `ready`, or `other`), outcome (`completed` or `aborted`), response status class (`2xx`, `3xx`, `4xx`, `5xx`, `other`, or `none` for an aborted response), and monotonic elapsed milliseconds from request handling to response finish or disconnect. Route classes depend on method, exact supported path, and whether health probes are enabled. Raw URLs, publication versions, headers, tokens and actor identifiers are not emitted. A closed connection is recorded at most once.

The callback runs in the server process and must be fast and nonblocking. Synchronous errors and rejected promises are ignored so telemetry failure does not break serving; the host must bound and monitor its exporter queue. An observation is not a durable audit record. Request completion measures server response completion, not confirmation that a client received the response, and excludes work done before the handler begins. An aborted request is separate from an HTTP status and should not automatically be counted as a server error.

`DataPlaneRequestMetrics` provides an optional process-local aggregator: construct it, pass `metrics.observe` to the Data Plane, and call `metrics.render()` for Prometheus text exposition. It reports request counters and cumulative duration histograms in seconds using fixed buckets from 5 ms through 10 seconds and `+Inf`. It accepts only the fixed route, outcome and status classes above, with at most 30 label combinations; invalid observations are rejected. Series appear only after an observation, counters reset on process restart, and overflow is rejected rather than producing invalid metrics. The host must provide and secure a scrape endpoint, monitor telemetry loss, supply service and deployment attributes from trusted configuration, and aggregate histogram buckets rather than averaging percentiles. This API does not provide distributed trace context, SLOs, retention or alerts; configure those at the host and collector with appropriate privacy, cardinality and operational ownership.
