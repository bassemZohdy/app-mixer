# Local environment promotion

The local control plane can transfer a published definition between separate repositories. `POST /promotion/export` with `{ "sourceEnvironment": "development", "version": 1 }` returns a versioned package containing the definition, source environment and version, and a SHA-256 digest of those fields. `POST /promotion/import` with `{ "package": ..., "targetEnvironment": "production", "expectedVersion": 0 }` checks the package, its digest, the target application ID, schema, target compatibility guard and current target version before appending a new immutable publication. Both routes require the control token. `expectedVersion` is zero for an empty target; otherwise it is the latest target version. A stale request returns 409. The target draft and historical publications are not changed.

Promotion provenance records the claimed source and target environments, source version, package digest, and preceding target version. SQLite writes the publication and both provenance records in one transaction. After a lost response, inspect target provenance and latest version before retrying; a retry with the original precondition cannot publish twice. Older publications without provenance remain unknown. The existing SQLite provenance table stores promotion base records as `publish`, with a separate immutable promotion table; readers must use the current repository API to distinguish them.

The export endpoint reads only published definitions. Environment names are operator-supplied labels and the digest checks consistency, not identity or authenticity. A trusted operator must authenticate both control planes, verify the source and target environment identities through a trusted channel, and authorize promotion. The local control-token API is a development prototype, not production identity, remote transport, signed artifacts, or actor-level audit. Do not place credentials or environment secrets in definitions. The host's publication guard must verify target runtime and extension compatibility. Promotion does not migrate business data or submit transactions. Schema migration, production authorization and authenticated remote promotion remain open.
