# Local agent event ingress

`SqliteAgentTriggers` stores an event and creates its queued run in one transaction in the same SQLite database as `SqliteAgentRuns`. The host supplies tenant and agent scope, an authenticated source and principal, event ID and type, JSON payload, pinned definition version, retry limit, deadline and maximum outstanding backlog. Event IDs deduplicate within a tenant, agent and source. A matching repeat returns the original run; a changed principal, event type or payload returns a conflict. Duplicate requests are checked before the backlog limit. Payloads are bounded to 256 KiB and can be retrieved by scope and run ID for a trusted worker.

`createAgentEventIngress` exposes `POST /events` with `{ "agentId": "...", "eventId": "...", "eventType": "...", "payload": ... }`. The host must provide `authenticate(request)`, returning a trusted tenant, principal and source, and `authorize(identity, event, definition)`. Identity fields in the body are rejected. The endpoint checks that the latest agent definition is enabled, rechecks its version after authorization, and enqueues a run with its retry and timeout settings. It returns 202 for a new event, 200 for a duplicate, 409 for a conflicting event, and 429 when the configured backlog is full. Authentication and authorization are repeated even for duplicates.

For signed webhook deliveries, configure `createSignedWebhookAuthenticator({sources, clock?, maxAgeSeconds?})` and pass the returned function as `authenticateRaw` instead of `authenticate` to `createAgentEventIngress`. Each trusted source has a unique `sourceId`, `tenantId`, `principalId` and secret `Uint8Array` of at least 32 randomly generated bytes. Source IDs select host-configured identity and keys; the request body never selects tenant or principal. For rotation, a source may include `previousSecrets` with up to two distinct prior keys alongside its current `secret`. Each must be 32 to 1024 bytes. Deploy the overlap, move senders to the new key, then deploy configuration without retired keys. Every accepted key grants the same source authority, so keep the overlap short and remove a compromised key immediately. The verifier snapshots all keys at construction; existing instances retain their old configuration until replaced. The host must deliver keys securely and coordinate rotation with senders.

Send the exact UTF-8 JSON bytes with `Content-Type: application/json`, `X-App-Mixer-Source`, `X-App-Mixer-Timestamp` (canonical decimal Unix seconds), and `X-App-Mixer-Signature`. The signature is `v1=` followed by lowercase hex HMAC-SHA256 using the source key over the UTF-8 bytes of `v1\n<timestamp>\n<sourceId>\n` followed immediately by the raw request body bytes. The verifier rejects duplicate security headers, unknown sources, invalid signatures and timestamps outside the configured symmetric clock window (300 seconds by default; maximum 3600). Keep clocks synchronized. Signatures are verified before JSON parsing; normal source authorization and definition checks still apply to each delivery, including duplicates. Persisted event-ID deduplication prevents the same source, agent and event ID from creating another run, including after the timestamp window; it does not prevent a sender with a valid key from signing new event IDs. Retain deduplication records for at least the desired replay horizon. Requests are limited to 256 KiB before authentication, so the host must enforce network-level rate, connection and request-time limits.

## GitHub webhooks

`createGithubWebhookAdapter({identity, agentId, eventType, secret, previousSecrets?})` returns `authenticateRaw` and `mapAuthenticatedBody` for `createAgentEventIngress`. Configure one host-selected source identity, target agent, and event type per endpoint. Configure the GitHub webhook to send JSON and use a high-entropy secret of 32 to 1024 bytes. Up to two previous keys can overlap during rotation; replace running instances to retire a key. The adapter follows [GitHub's HMAC-SHA256 body-signature protocol](https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries), rejecting missing, malformed, duplicate or incorrect signature headers before decoding the body. The host must authorize the source and validate the signed payload's repository, action and other relevant fields in the ingress `authorize` callback.

GitHub signs the body, not `X-GitHub-Delivery` or `X-GitHub-Event`. The adapter ignores both headers, uses the configured event type, and derives an event ID from the raw body hash. A captured signed body therefore deduplicates even if its unsigned headers are changed. Identical bodies from distinct legitimate events also deduplicate, and GitHub's signature contains no timestamp; retained deduplication records are needed for replay protection for as long as the secret and captured signatures may remain valid. Key reuse across endpoints can permit cross-endpoint replay, so use a unique secret per webhook. The host must secure transport, limit requests, and plan deduplication retention. A trusted `mapAuthenticatedBody` callback is available for other raw-authenticated integrations; it runs only after authentication and must derive authorization-relevant fields from authenticated data or trusted configuration.

## Stripe webhooks

`createStripeWebhookAdapter({identity, agentId, secret, previousSecrets?, clock?, toleranceSeconds?})` supplies raw authentication and mapping for `createAgentEventIngress`. Configure one trusted identity and agent per endpoint, and provision the endpoint's Stripe `whsec_` signing secret. The adapter implements Stripe's [timestamped HMAC-SHA256 signature protocol](https://docs.stripe.com/webhooks#verify-manually): it checks the raw body and one or more `v1` signatures, rejects duplicate signature headers and ambiguous timestamps, and checks both past and future timestamps against a nonzero window (300 seconds by default, maximum 3600). Keep clocks synchronized. Up to two previous secrets may overlap during key rotation; replace the running adapter to remove retired keys. Use distinct secrets per endpoint and protect them like credentials.

The adapter accepts Stripe snapshot events with `object: "event"`, a valid `evt_` ID and event type. It derives both event ID and type from the signed body; retries with a fresh signature still deduplicate by event ID, while a changed payload for the same ID conflicts. Thin events are not supported by this adapter. The ingress authorization callback must restrict event type, Stripe account, live/test mode and any other relevant signed fields to the configured tenant and agent. Authentication does not grant permission to execute capabilities or confirm business outcomes. The host must enforce HTTPS, network limits, retention and secure storage; event payloads are stored unencrypted. Keep deduplication records for the full retry and replay horizon.

The host must configure HTTPS, validate event schemas and permissions in `authorize`, and derive source identities independently of request body data. This protocol requires a sender that can produce the specified signature; provider-specific signing formats require a separate verifier. It is not an identity provider. It does not start a worker or automatically retry events. Separately configured timers and cron are described in [agent schedules](agent-schedules.md). Event payloads are stored unencrypted and may be sensitive; protect the database and backups. Idempotency records are retained indefinitely and need a host-managed retention policy appropriate to source replay windows.

Run claims enforce a per-tenant, per-agent concurrency limit within the same SQLite transaction. The host-driven worker uses the current manifest's `maxConcurrentRuns`; direct registry callers must supply their trusted limit (the default is 1). Running, pause-requested and cancel-requested attempts count until settled or explicitly recovered, including expired leases. This is local SQLite coordination; hosts must not bypass it with old binaries or direct writes and must reconcile an expired worker before retrying. Daily/token quotas and distributed coordination remain open.
