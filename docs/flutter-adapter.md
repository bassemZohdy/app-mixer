# Flutter renderer: initial subset

`adapters/flutter` contains a Flutter package with an initial A2UI v0.9.1 renderer for Text, Column, Row, Card, TextField and Button. It accepts create, incremental component and data-model updates, and delete surface messages for the App Mixer catalog or the basic catalog identifier. Accepting a catalog identifier does not imply support for the full catalog.

A host supplies `AppMixerA2UI` with `subscribe`, a function that receives a message callback and may return an unsubscribe callback, `onError`, and an optional `onAction` handler. The host must authorize and route actions. Text fields and buttons use Material widgets, so the host needs a Material ancestor and bounded horizontal constraints. Rows share available width among child subtrees containing text fields. A new subscription must replay the current state. The widget unsubscribes on replacement or disposal and ignores late messages. Updates are validated and applied atomically, with limits on surfaces, components, tree depth and expanded size. Incoming text is rendered as text and never executed.

Text supports literal values and absolute JSON pointer bindings. Model updates reject prototype-sensitive paths and keys, cycles, unsupported values, and structures over 10,000 nodes or 100 levels deep. TextField updates a non-root data path; Button sends only explicitly selected context to the host and is disabled without an action handler. Input and button callbacks from replaced surfaces are rejected. The full web catalog is not yet supported. The model uses JSON values; deleting an array element preserves its index while distinguishing it from an explicit null. Typography and layout parity are not complete: explicit `stretch` alignment is rejected and the default cross-axis alignment is centered to avoid unbounded layout errors. Platform integration and accessibility testing remain future work. P2-01 remains open until Flutter and React Native cover the supported web catalog and cross-platform parity is verified.

The Flutter workflow runs only for pull requests changing the Flutter package or its workflow. It downloads the pinned Flutter SDK and verifies its published SHA-256, then runs `flutter analyze` and widget tests. Shared layout, binding, action-context and invalid-message fixtures are also checked against the web and React Native implementations. On a machine with Flutter 3.35.5 installed, run `flutter pub get`, `flutter analyze`, and `flutter test` from `adapters/flutter`.
