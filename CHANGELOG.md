# Changelog

All notable changes to App Mixer are tracked here. Version numbers describe repository development, not released production features.

## [Unreleased] — 2026-10-28
### Added
- `oidc-discovery-boundaries.test.mjs`: boundary tests for OpenID Connect discovery (timeout and origin-count limits, URL length and character rules, credentials/query/fragment/scheme refusals, response status and content type, the 128 KiB metadata limit, invalid UTF-8, metadata shape, and the manager's authenticator checks). A mutation run showed 37% of small changes to the module went unnoticed; the caught share rises from 63.0% to 92.6%.
- `action-journal-boundaries.test.mjs` and `durable-runs-boundaries.test.mjs`: boundary tests for the action journal (action data limits, argument validation, re-invoking an action with different content, what an approval must match and the edge of its expiry, retry with the same key after a refusal, stale-verification protection) and the run registry (lease and deadline edges, per-agent concurrency and daily limits, the legal transitions). A mutation run showed 36% and 60% of small changes to these went unnoticed; the caught share rises from 63.7% to 89.8% and from 40.1% to 95.7%. `run-waits-boundaries.test.mjs` covers pausing a run for an approval or a delegation renewal, resuming it, failing it at its deadline with evidence, and the guards for unresolved actions and token reservations.
- `extension-approvals-boundaries.test.mjs`: boundary and fail-closed tests for the shared extension approval store, using a scripted query function (no database). A mutation run showed 37% of small changes went unnoticed (argument and decision validation, expiry edges, the checks on rows read back); the caught share rises from 62.6% to 96.1%.
- `approval-delegation-boundaries.test.mjs`: boundary tests for the human approval store and the delegation store (expiry edges, the 24-hour and thousand-per-run limits, separate `cancel` and `decide` permissions, a finished run, re-requests with other content, list limits). A mutation run showed 39% and 31% of small changes to these stores went unnoticed; the tests raise the caught share to 94.0% and 90.7%.
- `webhook-adapter-boundaries.test.mjs`: boundary and rejection tests for the generic signed, GitHub, Stripe, Slack and Standard Webhooks adapters. A mutation run showed 22% to 40% of small changes to these modules went unnoticed (the replay window's exact edge, single malformed headers and options, strict body decoding, several limits); the tests raise the caught share to between 94.7% and 100%.
- `scripts/mutate.mjs`, a small mutation tester, and `jwt-authenticator-boundaries.test.mjs`. Mutating the JWT authenticator showed 66 of 177 changes went unnoticed (62.7% caught); the new tests (single bad options, keys and headers, the 8192-character header limit, token age and issue-time limits, the actor returned by the host policy, `isIssuer`, key replacement or closing during the policy lookup) raise it to 85.9%, and the remaining survivors are repeated defensive checks.
- Automated accessibility checks with axe-core 4.14.0 (WCAG 2.0 to 2.2 A and AA plus best practices) in a real browser, for the web renderer's output for the shared fixture and for a freshly generated app (`browser-accessibility-axe.test.mjs` in `packages/web` and `packages/cli`, run in CI). axe-core is a new exact-pinned dev dependency.
- `scripts/bench-postgres.mjs` and a table in `docs/kubernetes-data-plane.md` for the PostgreSQL stores on the request path (also a durable run's create, claim and settle: about 40 a second for one worker, 190 for one agent however many workers, 400 to 640 across eight agents, unaffected by 200,000 finished runs): the revocation lookup does about 12,000 a second, while the capability audit append for one tenant is limited to about 330 to 430 a second (one counter row per tenant, held for each commit) and queues badly beyond that, but scales across tenants.
- `scripts/bench-data-plane.mjs`, a Data Plane load benchmark (requests per second, latency, CPU per request, and memory by quarter of the run to tell a leak from a plateau; `BENCH_ONLY` picks scenarios), and a capacity section in `docs/kubernetes-data-plane.md` with the first figures.
- A weekly CodeQL workflow (`codeql.yml`: JavaScript/TypeScript and the workflow files, `security-extended` queries, test code excluded). Its first run found 26 alerts; the ones that matter are fixed below, two `user-controlled-bypass` alerts on URL routing in `notice-https-receiver.ts` and `planes.ts` are false positives (the route only selects between two operations after the caller is authenticated), and the rest are in tests and CI scripts.
- A weekly `operating-systems.yml` workflow runs the unit tests on Windows and macOS (Linux arm64 has its own).
- A documented, unverified OpenShift section: an attempt on OpenShift Local could not deploy the manifests because the node was out of memory at 11 GB; the expected `restricted-v2` problem with the fixed `runAsUser: 1000` is described, not tested.
- A weekly `arm64.yml` workflow runs the unit tests and the PostgreSQL integration suites on native Linux arm64 runners (Graviton and Ampere nodes are common in Kubernetes); both passed on the first run.
- A weekly `postgres-versions.yml` workflow runs the PostgreSQL integration suites on PostgreSQL 14, 15 and 17 as well as the main job's 16 (all 65 tests passed on each in CI when first run), using the file list in `ci.yml`.
- A weekly `postgres-versions.yml` workflow runs the PostgreSQL integration suites on PostgreSQL 14, 15 and 17 as well as the main job's 16 (all 64 tests passed on each when first run), using the file list in `ci.yml`.
- An opt-in test against Ory Hydra (`APP_MIXER_TEST_HYDRA=docker`) and a documented list of identity provider requirements. Hydra's access tokens carry `typ: JWT`, which the authenticator refuses by design (it requires RFC 9068 `at+jwt`); everything else passed in a scratch build without that check.
- `createRemoteControlConnector` takes an optional `onAnchorError(error)`: a failing promotion-floor anchor was swallowed silently after a committed import and during the catch-up before the next one, which left rollback protection stale with no signal. A throwing callback is ignored.
- `scripts/live-github-delivery.mjs`: a live check that GitHub itself delivers signed events to the GitHub webhook adapter (a `ping`, the `push` test event twice, and a wrong signature refused through a temporary tunnel), cleaning up its webhook and tunnel. It passed on 2026-11-08; the documentation now says GitHub signs with the secret string's UTF-8 bytes.
- The alert failure drill now also starts a Grafana container, imports the shipped dashboard through the import API and runs every panel query against the drill's Prometheus: no panel errors, the `job` variable lists both jobs, and the panels fed by the drill's metrics show data.
- `createOpenAILimitedToolModel`: an OpenAI-compatible model that implements the token (and cost) limit contract for agents with a `tokenBudget`. It sends the provider an output cap derived from a conservative prompt bound, refuses a prompt that cannot fit before dispatch, turns SDK retries off and uses the provider's reported usage. A real model server (Ollama, qwen2.5:0.5b) stopped at the cap and its usage added up.
- The memory evaluation test can embed with a real model served by Ollama (`APP_MIXER_TEST_OLLAMA_URL`, `APP_MIXER_TEST_OLLAMA_MODEL`). With all-MiniLM and nomic-embed-text, semantic recall on the draft set rose from 0.79 to 0.98, and the HNSW index stayed at 0.98 to 0.99 of exact search; hybrid fusion remains worse than semantic search on paraphrases.
- A `cert-manager-tls-example` overlay and `cert-rotation.sh` (workflow `kubernetes-certificates.yml`): in kind, cert-manager issues the Data Plane's certificate; a renewal and a CA rotation reach both pods with no restart, and a client holding the CA bundle verifies throughout.
- The offline provisioning scenario now runs in a browser on an Android emulator (`packages/web/device-test/android-browser-storage.mjs`, workflow `web-android.yml`): the queue and publication survive a kill, cleared browser data is reported, and re-provisioning recovers. The same scenario runs in Safari on an iOS Simulator (`ios-browser-storage.mjs`, workflow `web-ios.yml`); both use `browser-storage-scenario.mjs`. The page, grant and server moved to `packages/web/test/support/provisioning-fixture.mjs`, shared with the headless-browser test.
- A test of two rollout pollers on one PostgreSQL journal through a source outage: the outage is retried, the promotion imports exactly once, and the documentation now says a poller that loses the claim to a live peer stops with a review flag, so run one poller per journal.
- `scripts/check-provider-idempotency.mjs` runs the idempotency conformance check against a provider's sandbox from a small config file (credentials from the environment, production refused), with tests against a conforming and a non-conforming local provider, and the owner's outbound contract (HTTP APIs that honour idempotency keys) is recorded in `docs/agent-action-journal.md`.
- The isolation benchmark was run at 100 tenants of 200 memories: a shared index found 0.909 of exact search's results and per-tenant indexes 0.999 at the same query time, but loading took 338 s against 179 s (docs/agent-memory.md). The benchmark now times the indexed search alone, and its figures were rerun at 20, 50 and 100 tenants. Index set-up itself is negligible (0.5 s for 100 scopes); the load-time ratio grows with the number of scopes, and the benchmark now prints `initializeSeconds`.
- A store-failover test for run workers (`postgres-run-failover.test.mjs`, `APP_MIXER_TEST_POSTGRES_FAILOVER=docker`, run in CI): the PostgreSQL primary is killed while two workers hold runs, a synchronous standby is promoted, and every run finishes with each effect applied exactly once. A shared cluster fixture backs it, and the run-node fixture ignores idle-connection errors so a failover does not crash it.
- `scripts/anchor-admin.mjs`: an operator tool to list, read and raise the file-based rollback anchors, and to lower one only with `--allow-lower` and a written reason; every change is appended to `anchor-admin.log`. The docs gain a recovery procedure for a rollback refusal, exercised in the restore test (re-applied state clears the refusals; the audit anchor is lowered only with the flag and a reason).
- The Kubernetes Data Plane anchors the revocation epoch in the same `APP_MIXER_RELEASE_FLOOR_ANCHOR_DIR`: token checks are denied while the revocation database's epoch is below the anchored epoch. The kind workflow provisions the epoch table and checks the copy to the anchor volume, the denial after the epoch is lowered, and recovery after it is restored.
- `PostgresJwtRevocations` and `PostgresExtensionApprovals` take an optional `epochAnchor`: a restored database whose revocation epoch (a new `app_mixer_jwt_revocation_epoch` table, created by `initialize()`) or approval epoch (the sum of approval revisions, no new table) is below the anchored epoch makes the check throw instead of re-activating a revoked token or re-granting a revoked approval. The restore test now shows all four anchored stores refusing.

- `PostgresCapabilityAudit` and `PostgresAuthenticationFailureAudit` take an optional `sequenceAnchor` (with `createFileSequenceAnchor` as a durable file-based implementation): a restored audit database whose sequence went back makes recording fail with "Audit log was rolled back" instead of reusing sequence numbers. The restore test shows both behaviours. The release floor and sequence anchors share one atomic file helper.
- The Kubernetes Data Plane takes `APP_MIXER_RELEASE_FLOOR_ANCHOR_DIR` (with the PostgreSQL floor mode) to keep the release floor on a separate volume and refuse a restored database; the `signed-jwt-tls-revocation-fresh-anchor-example` overlay, the admission example and its checks, and a kind step that lowers the database floor under a running Data Plane cover it. A failed release check is logged once a minute without database details.
- `PostgresPublicationReleaseRegistry` takes an optional `floorAnchor` held outside the database: a restored database whose floor is below the anchored floor makes `isAllowed` throw instead of allowing an older release, and an unreadable anchor fails closed. The restore test shows the detection. `createFileReleaseFloorAnchor(directory)` provides a durable file-based anchor (atomic writes, never lowers the floor, corrupt file fails closed).

### Changed
- The Data Plane serializes a publication once per request instead of twice (the ETag is the digest of the body it sends), and the new `immutablePublications` option lets a host keep the serialized body and ETag; the Kubernetes start-up script now uses it with a frozen snapshot instead of copying the publication on every request. Measured: a 1 MB publication went from 280 to 1,100 requests per second, 100 KB from 3,100 to 8,100 and a JWT-protected small one from 11,000 to 17,500, with a lower peak memory.
- The supported Node floor is now 22.22.2 (was 22.13.0): `engines`, README and CONTRIBUTING, the CI matrix, the kind workflow and the Docker base images. This unblocked `jsdom` 31 and the OpenTelemetry 3.x group (`@opentelemetry/api` 1.10.0, `core`, `sdk-trace`, `context-async-hooks`, `resources` 3.1.0, OTLP exporter 0.301.0), taken in this release; the exporter is also a root dev dependency so the collector tests resolve it, and the browser collector test's module server resolves packages' `#imports`.
### Fixed
- Web and React Native renderers reject sparse child lists with the controlled `Invalid children` error; array holes previously bypassed validation and surfaced as a raw TypeError (found by the renderer fuzz test).
- Queued agent runs start in creation order instead of run ID order (random UUIDs started them in random order): `SqliteAgentRuns` adds a `created_seq` column and `PostgresAgentRuns` an identity `sequence` column, both backfilled for existing databases.
- Agent memory scopes no longer become permanently unwritable after `10 x maxEntries` writes and deletes: `compactTombstones` (SQLite and PostgreSQL, `purge` permission, audited) removes tombstones in bounded passes.
- `SqliteOfflineQueue` no longer refuses a principal after 1,000 operations ever: only live operations count toward the cap, and a host-authorized `purge` removes settled history.
- Capability refusals before execution no longer strand staged business operations and offline items as `uncertain`: `SqliteStagedOperations.submit` returns the intent to `staged`, `SqliteOfflineQueue` retries within its attempt limit without consulting the classifier, and `PostgresOfflineExecutions` returns the key to `ready`. Execution errors stay uncertain.
- The PostgreSQL memory store quotes the identifiers it must place in index predicates and expressions through one validating helper (`sqlLiteral`) instead of interpolating them, and a test checks that every quoting character is refused.
- `PostgresAgentSchedules.fireDue` bounds its rescans (`maxScans`) and reports `scans` and `backlog`, so heavy contention or a long catch-up no longer rescans the due list without limit.
- `DevelopmentAgent` works on schema version 2 drafts (page descriptions, extension references and operations, `Extension` components); it previously refused every draft that was not version 1, including applications migrated to version 2.
- `DevelopmentProposals` no longer refuses new proposals forever after 100 have been created: only pending proposals count toward the limit and settled ones are evicted beyond a `settledLimit` bound.
- Capability refusals that happen before any effect (not found, forbidden, invalid input, a throwing policy, a failed attempt audit, and the configured runtime's own activity and delegation checks) no longer leave the agent action `uncertain` and the run awaiting operator reconciliation: `CapabilityRegistry` marks such errors with `Symbol.for('app-mixer.effect') === 'none'`, and both action journals return the action to `ready` (or `failed` once attempts are exhausted) and rethrow the original error. Unmarked dispatch errors stay uncertain.
- The CLI runs as a command on Windows: the entry was detected with a forward-slash suffix of `process.argv[1]`, so `node packages\cli\dist\index.js create demo` exited 0 without creating anything. The entry is now compared by resolved path.
- The offline queue's rollback anchor now detects selective substitution or deletion of individual item envelopes, not only whole-partition restores. The counter record carries an authenticated digest of every envelope, checked at open, on `list()` and before each write.
- Run and schedule configuration must be own plain data; schedules reject inherited fields with the controlled error instead of a raw TypeError.
- Agent manifests must be plain JSON data; values that satisfied validation through inherited fields, accessors or class instances are now rejected.
- Extension integrity digests must now use the canonical base64 spelling; non-canonical spellings that decoded to the same bytes were previously accepted.
