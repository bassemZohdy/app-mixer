# Changelog

All notable changes to App Mixer are tracked here. Version numbers describe repository development, not released production features.

## [Unreleased] — 2026-10-28
### Added
- `PostgresJwtRevocations` and `PostgresExtensionApprovals` take an optional `epochAnchor`: a restored database whose revocation epoch (a new `app_mixer_jwt_revocation_epoch` table, created by `initialize()`) or approval epoch (the sum of approval revisions, no new table) is below the anchored epoch makes the check throw instead of re-activating a revoked token or re-granting a revoked approval. The restore test now shows all four anchored stores refusing.
- The Android device check asserts that the reference headings are exposed with a role different from body text (the platform tree has no heading level).
- `PostgresCapabilityAudit` and `PostgresAuthenticationFailureAudit` take an optional `sequenceAnchor` (with `createFileSequenceAnchor` as a durable file-based implementation): a restored audit database whose sequence went back makes recording fail with "Audit log was rolled back" instead of reusing sequence numbers. The restore test shows both behaviours. The release floor and sequence anchors share one atomic file helper.
- The Kubernetes Data Plane takes `APP_MIXER_RELEASE_FLOOR_ANCHOR_DIR` (with the PostgreSQL floor mode) to keep the release floor on a separate volume and refuse a restored database; the `signed-jwt-tls-revocation-fresh-anchor-example` overlay, the admission example and its checks, and a kind step that lowers the database floor under a running Data Plane cover it. A failed release check is logged once a minute without database details.
- `PostgresPublicationReleaseRegistry` takes an optional `floorAnchor` held outside the database: a restored database whose floor is below the anchored floor makes `isAllowed` throw instead of allowing an older release, and an unreadable anchor fails closed. The restore test shows the detection. `createFileReleaseFloorAnchor(directory)` provides a durable file-based anchor (atomic writes, never lowers the floor, corrupt file fails closed).
- A backup-restore characterization test (`postgres-restore-rollback.test.mjs`, `APP_MIXER_TEST_POSTGRES_RESTORE=docker`, run in CI) and operator guidance: restoring an older PostgreSQL backup silently re-activates revoked tokens, lowers the release floor, re-grants revoked approvals and rewinds the audit log, because those stores keep no anchor outside their database.
- Owner decisions recorded: per-tenant (scoped) vector indexes for agent memory, and support for every current webhook adapter (`docs/agent-memory.md`, `docs/agent-event-ingress.md`). The "providers the product commits to supporting" checklist item is closed by that list.
- The React Native device checks place three rows justified to the start, centre and end and verify where each label lands across the screen width, on the Android emulator and the iOS simulator.
- A run-worker freeze test (`postgres-run-nodes.test.mjs`): a worker stopped with SIGSTOP past its lease is replaced by another node, and when resumed it dispatches nothing and cannot complete the run it lost; every effect stays applied once.
- A node-failure scenario for scheduled run workers (`node-failure.sh`, the `node-failure` job of the Agent pod recovery workflow): a kind worker node is killed under a running worker, the Deployment replaces the pod, and the survivor recovers the runs with every effect applied once. `run-supervisor.mjs verify` takes the minimum number of worker pods that must have done work.
- A failover drill for the PostgreSQL revocation store (`postgres-revocation-failover.test.mjs`, `APP_MIXER_TEST_POSTGRES_FAILOVER=docker`, run in CI): a revocation acknowledged by a synchronous standby survives killing the primary, and lookups deny while no primary exists; the release-floor registry keeps refusing lower releases on the promoted standby, extension approvals keep their grants, revocations and audit history, and the capability and authentication-failure audit logs keep their events and sequences.
- `scripts/bench-memory-isolation.mjs` compares shared and per-tenant HNSW indexes on pgvector (recall against exact search and latency); the measured result is in `docs/agent-memory.md`.
- `SqliteAgentRunMetrics` takes `includeApprovals` and exposes `app_mixer_agent_approvals{status}`, the number of human approvals by state, shown on the Grafana dashboard; `includeNoticeDeliveries` adds `app_mixer_agent_notice_deliveries{status}` the same way, and `includeTokens` adds `app_mixer_agent_token_calls{state}` and `app_mixer_agent_tokens{state}` for model-call token reservations; `includeCosts` adds `app_mixer_agent_cost_micros{currency,state}`; `includeMemories` adds `app_mixer_agent_memories{state}` (live, expired not yet purged, deleted).
- Webhook adapter tests that replay the signing examples published by Standard Webhooks and Slack (`vendor-vectors.test.mjs`).
- `deploy/observability/grafana-dashboard.json`: a Grafana dashboard for the Data Plane and agent metrics, with a test that its queries use only emitted metrics and labels.
### Changed
- The supported Node floor is now 22.22.2 (was 22.13.0): `engines`, README and CONTRIBUTING, the CI matrix, the kind workflow and the Docker base images. This unblocked `jsdom` 31 and the OpenTelemetry 3.x group (`@opentelemetry/api` 1.10.0, `core`, `sdk-trace`, `context-async-hooks`, `resources` 3.1.0, OTLP exporter 0.301.0), taken in this release; the exporter is also a root dev dependency so the collector tests resolve it, and the browser collector test's module server resolves packages' `#imports`.
### Fixed
- `PostgresAgentDefinitions.list` reads a page with three batch queries instead of six per agent, keeping the per-agent authorization sequence and the change check of `get`.
- `PostgresAgentMemory.list`, and with it semantic and hybrid search, reads a page of memories with two batch queries instead of two per memory (a 50-memory page: 3 queries instead of about 101) while keeping the per-record authorization before, during and after the read.
- Deleted business records no longer accumulate forever: `SqliteDataProvider.compactTombstones` removes tombstones in bounded passes.
- `EncryptedBrowserQueue` can be freed once it holds 1,000 items: a new `purge` deletes settled items in bounded passes while keeping the authenticated counter, state digest and rollback anchor consistent (a restored purged envelope is still detected).
- A `Text` bound to a number or boolean no longer renders as an empty string on the web, React Native and Flutter renderers: finite numbers and booleans are shown in their JSON spelling, and the shared accessibility fixture checks `3`, `2.5`, `4`, `true` and `false`.
- Request handlers that are async functions are wrapped (`guard`) so a rejection that escapes them ends the response instead of becoming an unhandled rejection; found by the new lint baseline together with an unawaited promise in the control plane's request runner.
- Queued agent runs start in creation order instead of run ID order (random UUIDs started them in random order): `SqliteAgentRuns` adds a `created_seq` column and `PostgresAgentRuns` an identity `sequence` column, both backfilled for existing databases.
- Agent memory scopes no longer become permanently unwritable after `10 x maxEntries` writes and deletes: `compactTombstones` (SQLite and PostgreSQL, `purge` permission, audited) removes tombstones in bounded passes.
- `SqliteOfflineQueue` no longer refuses a principal after 1,000 operations ever: only live operations count toward the cap, and a host-authorized `purge` removes settled history.
- Capability refusals before execution no longer strand staged business operations and offline items as `uncertain`: `SqliteStagedOperations.submit` returns the intent to `staged`, `SqliteOfflineQueue` retries within its attempt limit without consulting the classifier, and `PostgresOfflineExecutions` returns the key to `ready`. Execution errors stay uncertain.
- The PostgreSQL memory store quotes the identifiers it must place in index predicates and expressions through one validating helper (`sqlLiteral`) instead of interpolating them, and a test checks that every quoting character is refused.
- `PostgresAgentSchedules.fireDue` bounds its rescans (`maxScans`) and reports `scans` and `backlog`, so heavy contention or a long catch-up no longer rescans the due list without limit.
- `DevelopmentAgent` works on schema version 2 drafts (page descriptions, extension references and operations, `Extension` components); it previously refused every draft that was not version 1, including applications migrated to version 2.
- `DevelopmentProposals` no longer refuses new proposals forever after 100 have been created: only pending proposals count toward the limit and settled ones are evicted beyond a `settledLimit` bound.
- Capability refusals that happen before any effect (not found, forbidden, invalid input, a throwing policy, a failed attempt audit, and the configured runtime's own activity and delegation checks) no longer leave the agent action `uncertain` and the run awaiting operator reconciliation: `CapabilityRegistry` marks such errors with `Symbol.for('app-mixer.effect') === 'none'`, and both action journals return the action to `ready` (or `failed` once attempts are exhausted) and rethrow the original error. Unmarked dispatch errors stay uncertain.
- The CLI runs as a command on Windows: the entry was detected with a forward-slash suffix of `process.argv[1]`, so `node packages\cli\dist\index.js create demo` exited 0 without creating anything. The entry is now compared by resolved path.
- The offline queue's rollback anchor now detects selective substitution or deletion of individual item envelopes, not only whole-partition restores. The counter record carries an authenticated digest of every envelope, checked at open, on `list()` and before each write.
- Run and schedule configuration must be own plain data; schedules reject inherited fields with the controlled error instead of a raw TypeError.
- Agent manifests must be plain JSON data; values that satisfied validation through inherited fields, accessors or class instances are now rejected.
- Extension integrity digests must now use the canonical base64 spelling; non-canonical spellings that decoded to the same bytes were previously accepted.
### Added
- ADR 0011 records why `@app-mixer/core` keeps its dependency on the web renderer (two modules use it; revisit before publishing).
- `APP_MIXER_METRICS_BIND=0.0.0.0` opens the Data Plane metrics listener to the pod network (default stays loopback; token scope still mandatory), the admission example allows it, a NetworkPolicy example admits labelled scraper pods, and the kind workflow scrapes from another pod.
- One shared identifier validator and non-negative integer check per package (`validation.ts`) replace 49 identical identifier validators and 22 integer checks; a test caps the copies so they cannot spread again.
- Notice retention: `SqliteAgentNotices.prune` (notices with their receipts and delivery history, keeping undelivered work, with an immutable record of each prune) and `SqliteAgentNoticeReceiver.prune` (acknowledged notices), under a new `prune` access, bounded and oldest first; the immutability triggers are dropped and recreated inside the same transaction.
- Schema versions: migrating stores record their layout in `app_mixer_schema` and refuse a database written by a newer release (recorded for the agent run registry on SQLite and PostgreSQL and for staged operations), documented in `docs/schema-versions.md`.
- `npm run previews` (`scripts/sync-editor-previews.mjs`) copies the schema parser the generated record editor shares with the control plane's inert preview from the template into the preview module, escaped for a template literal; a test fails when the copy is stale and checks the escaping.
- The web renderer patches bound `Text` and `TextField` nodes in place on data-only updates when every rendered component is built in (about 20 times faster on a 998-component surface: 0.7 against 15 ms per update); custom components and `updateComponents` still rebuild. A test compares every step with a full render and checks that no element is created, and `scripts/bench-renderer.mjs` is the benchmark.
- `scripts/bench-sqlite.mjs`, a multi-process SQLite contention benchmark (rollback journal against WAL: 144 against 436 transactions per second on the development machine), documented in `docs/sqlite-stores.md` and smoke-tested.
- Stable hooks on every renderer: `data-component-id` and `data-variant` on the web, `testID` plus a host-supplied `variantStyles` prop on React Native, `ValueKey('a2ui:<id>')` on Flutter, and a filled button for the `primary` Button variant on Flutter. Colors stay with the host theme (documented in `docs/a2ui-renderer.md`).
- The PostgreSQL run supervisor ignores lost races by the `lost_race` error code instead of a message regex (30 throw sites in the run, journal and budget stores converted), and the disconnected promotion importer recognises a definite refusal by a `conflict` code first; a look-alike message is no longer silently ignored.
- `scripts/wait-for.mjs`, a condition poller with a real deadline and a named failure (the last probe error is kept as the cause), replaces eight hand-written polling loops in tests; a ratchet stops the number of inline sleeps in tests from growing.
- `exactOptionalPropertyTypes` is on in the shared TypeScript configuration: optional properties that receive `undefined` are declared as such, and values passed to LangChain and `fetch` option types that reject `undefined` are spread conditionally.
- In-range dependency updates: `@langchain/langgraph` 1.5.3 to 1.7.1, `@langchain/core` 1.3.5, `@langchain/langgraph-checkpoint` 1.2.2, `@ag-ui/core` 1.0.4 and `fake-indexeddb` 6.2.7 (full suite green, `npm audit --omit=dev` clean).
- CI caches the five pinned container-test images (Keycloak, SeaweedFS, OpenTelemetry Collector, Prometheus, Alertmanager) with `actions/cache`, keyed by the image list that `.github/scripts/docker-images.mjs` derives from the tests.
- The capability server maps its statuses by `AppMixerError` code (new codes `denied` and `unavailable`; 23 more throw sites converted), still honouring the documented messages for plain errors from host executors and providers, which keeps the generated offline runtime's conflict handling working.
- `AgentError` (codes `invalid`, `denied`, `not_found`, `conflict`, `limit`) and `agentErrorStatus`: the approval, event-ingress and metrics servers map by code (33 throw sites converted, messages unchanged, documented legacy messages still honoured); eight places that discarded the original failure (OIDC discovery, JWKS refresh, remote promotion export and signing, remote control discovery, floor and export, notice transport) now keep it as `cause`.
- `SqliteDevelopmentProposals`: a durable proposal store with the same contract as the in-memory one (pending proposals survive a restart), accepted by `createDevelopmentPlanes` through a new `ProposalStore` interface.
- All 26 SQLite stores open their databases in WAL mode (readers no longer wait behind the writer; `synchronous` stays `FULL`), with `docs/sqlite-stores.md` on the file layout and consistent backups and a test that fails for any store source that opens SQLite without it.
- `AppMixerError` (codes `invalid`, `not_found`, `conflict`, `limit`) and `httpStatus`: the control and Data Plane map their expected refusals by code instead of comparing message strings (53 throw sites in core converted, messages unchanged); a plain `Error` with a matching message is now a 500.
- A lint baseline (`npm run lint`, run in CI): typescript-eslint with `no-floating-promises`, `no-misused-promises`, `await-thenable` and unused variables over every package's sources, plus an `.editorconfig`. The first run found six issues, all fixed.

- `PostgresAgentCostBudget` caps an agent's daily model spend across runs and nodes on the shared PostgreSQL run registry. Reservations are lease-fenced and admitted under one per-agent lock, a provider overrun stops every node, and runs with open reservations settle as uncertain. A four-process race admits exactly the budget every time.

A two-replica Kubernetes Deployment test in kind crashes a worker mid-run and rolls the Deployment, and every external effect is applied exactly once.

A two-process test with one node killed shows each occurrence fired once with no gaps.
